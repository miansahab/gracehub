How it works

Users authenticate only through Entra ID SSO; accounts provision and deactivate from the directory (deactivated access ends within 15 min). No passwords stored here.

Access is role-based across three levels — platform role, department scope, record-level. Checks run server-side on every call. Admins manage it all in-app; sensitive fields carry visibility flags. Everything is encrypted and written to a tamper-proof audit log.

How it works

Four connectors keep GRACE Hub in step with the org's existing systems. All sync is queued and retryable with an admin-visible log, error queue and alerting on repeated failures.

Each data domain has one designated source of truth (QuickBooks = ledger, GRACE Hub = donors/grants); Bill.com approval state reconciles with the workflow engine to avoid dual approvals. Credentials live in a secrets manager.

21 Delivery Phases & MVP Section 10 · roadmap
P1 · 12–16w
Core Infrastructure — Entra SSO & M365, user/role mgmt, central dashboard, global search, docs, grants + donor CRM (core), QuickBooks & Bill.com, comms (core), workflow engine, basic reporting, audit logs
P2 · 8–12w
Operational Modules — events, board packet wizard, programs, advanced finance & grants, moves management, collaboration, AI-assisted content, mobile optimization, Knowledge Center
P3 · 8–10w
Intelligence & Automation — AI assistant, AI search, predictive dashboards, automated reporting, workflow intelligence, exec insights, advanced analytics, benchmarking
P4 · future
Enterprise Expansion — white-label, multi-org tenancy, subscriptions, partner portals, public APIs, module marketplace (out of scope now)
MVP — infra + security · central dashboard + exec reporting · donor CRM + grants · finance integrations + approvals · docs + search · comms with workflow
How it works

Build proceeds in four phases. Phase 1 stands up the shared platform and the revenue-critical modules; later phases layer on operational depth, then intelligence. Phase 4 is future architecture the build must not preclude.

Every requirement ID in this set maps to a test case in the traceability matrix, and each phase is accepted only when all "must" requirements pass with a completed security review.
